# nightwatch

Nightwatch soll ein oder mehrere E-Mail-Postfächer überwachen auf Benachrichtigungen von zum Beispiel einer Backup-Software, Firmware-Update-Meldung oder Meldungen eines Routers. Die Leitung ist down, Leitung ist ab. Die Besonderheit soll sicherlich sein, wenn eine Benachrichtigung nicht mehr kommt, also eine E-Mail nicht mehr kommt, dann ist das ja wie wenn das Monitoring down wäre. Sprich, wenn man in einem E-Mail-Postfach nur auf Fehlermeldungen zum Beispiel der Backup-Software überwacht, würde man nicht mehr mitbekommen, wenn die Backup-Software überhaupt nicht läuft. Denn wenn keine Benachrichtigung kommt über den Fehler, würde man ja denken, alles ist in Ordnung. Wenn man aber das Postfach voll hat von OK-Meldungen, alles ist in Ordnung, dann werden die Mitarbeiter natürlich anfangen und durchscrollen und ihnen nicht auffallen, wenn da zwischendrin etwas fehlt. Deswegen muss das automatisch überwacht werden. Der Use Case ist klar. Und dieses Werkzeug soll eigenständig funktionieren, nicht abhängig sein von Drittanbietern, eine komplette Automatisierung, die man sich zum Beispiel mit Docker auf einer Umgebung im eigenen Netzwerk installieren kann oder vorzugsweise zum Beispiel bei DigitalOcean oder eben innerhalb eines Azure-Containers. Wobei wir so etwas wie ein Docker-Template oder Portainer-Template oder eben etwas auf dem Marktplatz von Digital Ocean zur Verteilung vorziehen würden. Gleichzeitig muss es ein Updatesystem geben, dass wenn ein Update von Nightwatch, also neue Commits, PRs verfügbar sind, dass die Anwender direkt sich das Update ziehen können. Zielgruppe sind Unternehmen, Unternehmen im IT-Markt, IT-Systemhäuser, Managed Service Provider, vielleicht Druckerspezialisten, die von ihren Druckern Nachrichten bekommen usw.
